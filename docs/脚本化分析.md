 # ActionCoach SKILL.md 脚本化分析
 
 ## 为什么要脚本化？
 
 当前 SKILL.md 全文约 19KB（379 行），其中大量篇幅用于描述**数据操作逻辑**（记录积分、保存计划、切换状态等）。每次 LLM 执行 skill 时都必须"阅读"这些文字指令再执行，消耗大量 token。
 
 脚本化的核心思路是：**将"怎么做"（操作逻辑）从 prompt 移到脚本里，prompt 只保留"什么时候做什么"（触发逻辑）**。
 
 ## 可脚本化的组件
 
 ### 1. 积分记账系统（Points Ledger）— 节省量：~60 行
 当前 SKILL.md 中用约 30 行描述积分规则 + 30 行描述交互和展示。脚本化后只保留"调用积分系统脚本"一句话。
 
 ### 2. 每日计划状态管理（Daily Plan State）— 节省量：~50 行
 当前详细描述了计划创建、check-off 解析、进度更新。脚本化后用脚本管理计划数据的存储和更新。
 
 ### 3. 状态机引擎（State Machine）— 节省量：~40 行
 当前描述了 Silent / Stuck / Done / Paused 的转换条件和协议。脚本化后由脚本维护状态转换逻辑。
 
 ### 4. 周报生成器（Weekly Review）— 节省量：~30 行
 当前描述了周报格式、完成率计算、最佳一天判断。脚本化后由脚本自动计算并生成结构化文本。
 
 ### 5. 教练配置管理（Coach Config）— 节省量：~20 行
 当前 Step 5 有保存配置的描述。脚本化后统一管理教练配置的持久化。
 
 ## 脚本架构方案
 
 **语言**：Python（跨平台、无外部依赖、仅用标准库 json+os+datetime）
 **存储**：JSON 文件，存于 `scripts/data/` 目录，按用户 ID 分文件
 **CLI 接口**：统一入口 `scripts/ac.py`，子命令 `points|plan|state|weekly|config`
 **返回值**：stdout JSON + 格式化文本，便于 LLM 直接使用
 
 脚本化后 SKILL.md 预计从 ~380 行缩减到 ~220 行，token 消耗降低约 40%。
 
 | 指标 | 脚本化前 | 脚本化后 |
 |---|---|---|
 | SKILL.md 总行数 | ~380 行 | ~220 行 |
 | 每次执行 token 消耗 | 高（重复读取操作逻辑） | 低（只读取触发逻辑） |
 | 数据一致性 | 依赖 LLM 记忆 | 持久化 JSON 存储 |
 | 复杂计算 | LLM 现场计算，易出错 | 脚本精确计算 |
